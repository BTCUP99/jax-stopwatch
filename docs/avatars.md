# 形象制作规范

给画图的人或 AI 出图 Agent。按本规范交付的一套图放进仓库的 `avatars/<形象ID>/`，控制台“形象管理”会自动列出，一键转换并经 USB 写入设备；多套之间随时切换，不需要刷机。

仓库自带三套示例：[糯邮](../avatars/nuo-courier/)、[弦核](../avatars/orbit-warden/)、[小主播](../avatars/little-host/)。

## 1. 设备与画布

| 项目 | 值 |
|---|---|
| 屏幕 | 1.75 英寸圆形 AMOLED，466×466，纯黑即不发光 |
| 形象画布 | **386×386**，居中显示（四周各留 40px 黑边） |
| 背景 | **纯黑 #000000**，不要透明底、渐变、纹理或暗角 |
| 交付格式 | PNG，sRGB，不透明（无 alpha），8 位 |
| 设备内格式 | Mac 自动转为 JPEG（质量约 85），单张目标 ≤ 40KB |

画布内切圆就是屏幕上的可视范围：四个角会被裁掉，**主体必须在直径 386 的圆内**，轮廓只能以这个圆或造型本身结束，见 2.1。

## 2. 安全区（画布坐标，左上角为 0,0）

屏幕上叠加的界面会盖住以下区域，**不要放五官或重要细节**：

| 区域 | 画布范围 | 叠加内容 |
|---|---|---|
| 顶部 | y < 20，x 125–261 | 时间（黑底圆角条） |
| 底部 | y > 366，x 103–283 | 状态栏：助手名、连接图标、电量 |
| 右侧 | x > 335，y 70–310 | 提醒标识（最多 5 个圆形徽章，半径 20） |

字幕气泡会在说话时出现在画面下半部，但它会短暂遮挡，不需要避让。

建议：**脸部（眼睛到嘴）放在画布中心 260×200 的范围内**，头发可以延伸到顶部，身体可以延伸到底部（按 2.1 以圆弧结束）。

### 2.1 轮廓：只能以圆结束，不能有直线切口

屏幕是圆的，画面里**唯一允许的边界是画布圆**（直径 386，与屏幕同心）。水平或竖直的直线截断——画布边、为避让遮挡区画的方框、原照片的取景框——在圆屏上都是一道显眼的切口。主体轮廓只能用下面两种方式之一结束：

| 构图 | 怎么结束 | 适合 |
|---|---|---|
| **A. 完整造型** | 角色整个画完，脚、底座、尾巴、衣摆自然收尾，四周留黑 | 卡通、Q 版、全身照 |
| **B. 圆周出血** | 身体（肩、衣服、坐垫等）一直画到画布圆外，再用直径 386 的圆形蒙版裁掉；结束处是一段与屏幕同心的圆弧 | 胸像、半身像、只拍到半身的照片 |

- 不要把主体截在画面中间的一条横线或竖线上（例如半身像在 y≈330 处平切、人像左右沿照片边缘竖切）。造型本身的平边（平底的脚、底座、方形头顶）不算切口。
- 照片人物不够长、到不了圆周：先扩图把衣服和身体补到圆外，再做圆形蒙版（B）；或者用完整人物并整体缩进圆内（A）。两者都做不到时，最后手段是沿圆弧做 ≥ 24px 的柔和渐隐到纯黑，渐隐的边界同样是圆弧而不是直线。
- 第 2 节的遮挡区只约束**五官和重要细节**。头发、肩膀、衣服可以从遮挡区下面穿过（界面画在图上面，自带黑底），不要为了避让遮挡区把主体裁成方块或把遮挡区涂黑。
- 主体要撑满圆：轮廓最外沿大致到离中心 150px 以上（B 构图到 193），不要在大圆里缩成一个小方块。

## 3. 必需帧：16 张（4 种嘴型 × 4 种眼睛）

文件名 `base_m{嘴}_e{眼}.png`，嘴 0–3，眼 0–3：

| 编号 | 嘴型 m | 眼睛 e |
|---|---|---|
| 0 | 闭嘴（自然微笑） | 完全睁开 |
| 1 | 微张（说话轻音） | 微垂（放松，约睁开 80%） |
| 2 | 半张（普通发音） | 半闭（约 40%） |
| 3 | 大张（重音、元音 a/o） | 完全闭上 |

设备如何使用：
- **说话**：随语音音量在 m0–m3 之间快速切换，所以四张嘴型必须是**同一张嘴的连续开合**，形状过渡自然。
- **眨眼与闭眼**：眨眼和闭眼过渡时依次使用 e0 → e3，所以眼睛也要是**同一双眼的连续闭合**。
- 嘴和眼会任意组合（例如说话时眨眼），16 张都要画齐。

**最重要的要求：除了嘴和眼睛，16 张图其余像素完全一致。** 头发、脸型、身体、光影、位置、配色一个像素都不能动，否则说话时整张图会抖动闪烁。推荐做法：先画一张底图（m0_e0），再只修改眼睛和嘴的区域生成其余 15 张。

参考：仓库自带的三套形象（`avatars/*/preview.png` 是 4×4 拼图），以及上游内置脸 `firmware/data_stopwatch/base_m*_e*.jpg`，可以对照帧的含义和幅度。

## 4. 可选帧

| 文件 | 含义 | 状态 |
|---|---|---|
| `happy.png` | 开心表情，用于提醒到达、任务完成，要求见 4.1 | 第一阶段支持 |
| `giggle_1.png`、`giggle_2.png` | 嘻嘻调皮：轻点屏幕时播放，要求见 4.2 | 固件 0.4.0 支持 |
| `laugh_1.png`、`laugh_2.png` | 哈哈大笑：快速连点三下时播放，要求见 4.2 | 固件 0.4.0 支持（0.5.0 起改为连点触发） |
| `idle_00.png` … `idle_11.png` | 待机循环（呼吸、轻微晃头发），8–12 帧，首尾可无缝衔接 | 第二阶段，固件尚未支持 |
| `think_00.png` … `think_07.png` | 思考中（助手执行任务时），循环 | 第二阶段 |
| `listen.png` | 倾听（按住 A 录音时），可以是侧耳、专注表情 | 第二阶段 |

第二阶段的帧可以先画，同样遵守「只改动画部位、其余像素不变」的原则；等固件支持后直接可用。

### 4.1 开心表情 `happy.png`

用途：X 提醒到达、助手任务完成时短暂显示（约 1–2 秒），然后回到基础帧。它是整套里**情绪最明显的一张**，一眼就要看出“开心”，不能只是平静地闭眼。

**必须和 16 张基础帧都不同。** 特别是不能直接复用 `base_m0_e3`（闭嘴 + 闭眼）。基础帧的 e3 是“放松闭眼”，happy 是“笑到眯眼”，两者要明显区分。

| 部位 | 要求 |
|---|---|
| 眼睛 | 笑眼：向上弯的弧线（^^），比 e3 弯得更明显、更饱满；可以略微上提，表现“笑得眯起来” |
| 嘴 | 张开的笑，例如 D 形或上宽下窄的开口笑，可露出口腔或舌头的色块；比 m0 的微笑大一圈。不要用 m1–m3 的说话嘴型 |
| 脸颊 | 腮红比基础帧更明显（加深或扩大），角色本来没有腮红的，可以加一点暖色光晕或亮度提升 |
| 点缀（可选） | 头旁边 1–3 个小星星、音符或闪光等简单符号，形状要大而简洁；必须在画布圆内，且不进入第 2 节的遮挡区 |
| 身体与其余部分 | 头发、脸型、身体、配饰、位置、光影与 m0_e0 **像素一致**，切换时不跳动 |

改动范围：只改脸部（眼、嘴、脸颊）和可选点缀所在的位置，整体仍在中心 260×200 的建议区附近，其余像素差为 0。

按角色性格调整幅度：温和的角色可以是“眯眼 + 张嘴笑 + 腮红”，安静克制的角色可以是“笑眼弧 + 小开口笑 + 发光部件稍亮”，但都要比基础帧明显开心。

规格和基础帧相同：386×386、不透明、纯黑底，转为 JPEG（质量 85）后 ≤ 40KB。preview.png 不需要包含 happy，可另外附一张 `happy-preview.png`，左右并排放 `base_m0_e0` 和 `happy`，方便对比。

### 4.2 触摸表情 `giggle_*.png` / `laugh_*.png`

用户触摸首页上的形象时播放，**只有画面、不出声**。每种 2 帧，设备交替播放约 1.5–2 秒后回到基础帧：

| 反应 | 触发 | 播放 | 情绪 |
|---|---|---|---|
| 嘻嘻调皮 `giggle_1` ↔ `giggle_2` | 轻点一下 | 每帧约 0.24 秒，共约 1.6 秒 | 被戳了一下，俏皮、偷笑，有点得意 |
| 哈哈大笑 `laugh_1` ↔ `laugh_2` | 快速连点三下（第一下先嘻嘻，第三下接着大笑） | 每帧约 0.18 秒，共约 2 秒 | 被挠痒痒，笑得停不下来，比 happy 更夸张 |

| 部位 | 嘻嘻调皮 | 哈哈大笑 |
|---|---|---|
| 眼睛 | 一只眨眼（wink）、另一只笑眼；或两眼斜向一侧眯起偷笑。两帧可以换一边眨，或从半眨到全眨 | 笑到眯成弧线（^^），可加一两滴笑出的泪花；两帧弯度略有不同，看起来在抖 |
| 嘴 | 抿嘴偷笑、歪嘴笑，或吐一点舌头；两帧在“抿嘴”和“吐舌/咧嘴”之间切换 | 大张开的笑（比 happy 更大），两帧一张一收（开得最大 ↔ 稍合），形成“哈—哈—”的节奏 |
| 脸颊 | 腮红略加深 | 腮红明显加深、范围扩大 |
| 点缀（可选） | 小音符、小爱心、“嘻”字样的简单符号，1–2 个 | 头两侧 2–3 道“笑纹”或小星星，两帧位置略变，制造抖动感 |

要求：

- 两帧之间、以及与 `base_m0_e0` 之间，**脸部和点缀以外像素差为 0**（头发、身体、配饰、位置都不动），和 4.1 一样。动感只靠五官和点缀的变化来表现。
- 4 张都要和 16 张基础帧、`happy.png` 明显不同；`giggle` 和 `laugh` 一眼能分出“调皮”和“大笑”。
- 点缀必须在画布圆内，不进入第 2 节的遮挡区。
- 按角色性格调整幅度：克制的角色可以笑得收敛一些，但仍要比基础帧和 happy 更有动感。
- 规格与基础帧相同：386×386、不透明、纯黑底，JPEG（质量 85）后每张 ≤ 40KB。
- 附一张 `touch-preview.png`：一行 5 格，依次为 `base_m0_e0`、`giggle_1`、`giggle_2`、`laugh_1`、`laugh_2`。

缺少这些帧时设备会退回显示 `happy.png`（单帧）；连 happy 都没有的形象（如内置默认脸）不做触摸反应。

## 5. 风格与内容

- 原创角色，**不要使用现有动漫、游戏、品牌的角色或商标**。
- 黑底屏幕上要清楚：主体以中高亮度为主，边缘干净，避免大面积深色衣服和黑底融为一体。
- 线条不要太细，屏幕小、观看距离远，细节宜简洁；避免噪点、颗粒和细碎纹理（会让 JPEG 变大、变花）。
- 每套形象画风统一；不同套之间可以完全不同（例如一套人物、一套动物、一套极简表情）。

## 6. 交付结构

每套放一个文件夹：`avatars/<形象ID>/`，形象 ID 用 1–20 位小写英文、数字和连字符，例如 `snow-girl`、`cat-orange`。

```
avatars/snow-girl/
├── avatar.json          # 必需，描述信息
├── base_m0_e0.png … base_m3_e3.png   # 必需，16 张
├── happy.png            # 可选
├── giggle_1.png giggle_2.png laugh_1.png laugh_2.png   # 可选，触摸表情（4.2）
├── idle_00.png …        # 可选（第二阶段）
└── preview.png          # 必需，4×4 拼图预览：行=嘴 m0–m3，列=眼 e0–e3
```

`avatar.json`：

```json
{
  "id": "snow-girl",
  "name": "雪团",
  "version": 1,
  "description": "银发少女，浅蓝和服",
  "frames": { "base": 16, "happy": true, "giggle": 2, "laugh": 2, "idle": 0, "think": 0, "listen": false }
}
```

## 7. 交付前自检

- [ ] 16 张 `base_m*_e*.png` 齐全，全部 386×386、不透明、纯黑背景
- [ ] 任意两张之间，嘴和眼以外的像素差为 0（可用图像差分检查）
- [ ] 嘴型 m0→m3 是逐步张开，眼睛 e0→e3 是逐步闭合
- [ ] 五官不在第 2 节的遮挡区域内
- [ ] 轮廓没有直线切口（2.1）：用 `check_avatar.py` 检查没有 ✗，! 项在圆屏预览上逐个确认是造型本身的平边
- [ ] 如有 `happy.png`：与 16 张基础帧都不相同（不能等于 m0_e3），脸部以外与 m0_e0 像素差为 0，点缀不进遮挡区
- [ ] 如有触摸表情：`giggle_1/2`、`laugh_1/2` 四张齐全，各自与基础帧、happy 都不相同，脸部和点缀以外与 m0_e0 像素差为 0；已生成 `touch-preview.png`
- [ ] `preview.png` 和 `avatar.json` 已生成
- [ ] 单张 PNG 转 JPEG（质量 85）后 ≤ 40KB，整套 ≤ 0.8MB

## 8. 容量参考

设备形象存储区（LittleFS）共约 5.4MB，其中上游内置图片约占 1.9MB，**留给上传形象的约 3.4MB**。上传后每套实际占用（JPEG）：

| 内容 | 每套占用 |
|---|---|
| 16 张基础帧 + 开心表情 | 约 0.24–0.38MB |
| 触摸表情 4 张（4.2，固件 0.4.0） | 另加约 56–87KB |
| 仓库自带三套（含触摸表情）合计 | 约 1.2MB，装好后设备约剩 2.2MB |

按每套 0.3–0.5MB 估算，上传的形象合计约能放 8–10 套（自带三套之外再放 5–6 套），建议设备上保持在 8 套以内、留约 0.4MB 余量，方便重传改版后变大的形象；待机动画等第二阶段帧会让每套增至约 0.8–1MB。上传前控制台会显示设备已用/总量，空间不足时上传会被拒绝（设备始终保留 64KB 余量），可先删除不用的形象。同一时间只加载当前一套，多套不增加运行内存。

## 9. 设备上如何存放

- 上传时 Mac（`src/avatars.py`）把 PNG 转成基线 JPEG（质量 85、4:2:0），按 4KB 分块写入设备 LittleFS 的 `/av/<id>/`，每个文件 CRC-32 校验通过后才替换旧文件，另写一份 `meta.json`。
- 当前形象记在 `/av/active`，重启后保持。设备优先读当前形象目录里的同名图，缺的（如上游的摸头、转头动画）回落到根目录的内置图。
- 开心表情：任务播报或 X 提醒播报结束、设备回到待机后显示 `happy.jpg` 2 秒；开始录音立即取消。
- 触摸表情（固件 0.4.0，0.5.0 起连点触发大笑）：待机时轻点形象播放 `giggle_1/2.jpg`，快速连点三下播放 `laugh_1/2.jpg`；缺帧时显示 `happy.jpg`，再没有则不反应。控制台“形象管理”可关闭。
- 滑动切换（固件 0.5.0）：在首页左右快速滑动，按“内置形象 → 已上传的形象（按 ID 排序）”循环切换，与控制台列表顺序一致；只有完整的套（16 张基础帧齐全）参与。切换写入 `/av/active`，重启后保持，不需要连着 Mac。状态栏上方画一排页码小圆点（在第 2 节的底部遮挡区内，不会盖住五官）。

## 10. 给 AI 出图的建议

1. 先出一张高分辨率主视觉（角色全身、纯黑背景），定下造型和配色。
2. 只用这张主视觉生成 386×386 的 `m0_e0` 底图；之后**只在眼睛和嘴的区域**合成其余 15 帧和开心表情，不要让模型分别重画整张图，否则身体会抖。
3. 先定构图 A 或 B（2.1）。照片改形象：先把人物抠到纯黑底，再整体缩进圆内（A），或扩图补齐身体后用圆形蒙版（B）；不要沿照片边框直接裁成方块。
4. 用图像差分自检第 7 节的每一条，并运行 `.venv/bin/python scripts/check_avatar.py avatars/<形象ID> --preview 圆屏预览.png`（检查轮廓切口、圆外像素，画出手表上的实际样子），再在控制台上传、到设备上看实际效果。
