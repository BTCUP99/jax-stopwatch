# 形象制作规范

给画图的人或 AI 出图 Agent。按本规范交付的一套图放进仓库的 `avatars/<形象ID>/`，控制台“形象管理”会自动列出，一键转换并经 USB 写入设备；多套之间随时切换，不需要刷机。

仓库自带三套示例：[糯邮](../avatars/nuo-courier/)、[弦核](../avatars/orbit-warden/)、[小主播](../avatars/little-host/)。

## 1. 设备与画布

| 项目 | 值 |
|---|---|
| 屏幕 | 1.75 英寸圆形 AMOLED，466×466，纯黑即不发光 |
| 形象画布 | **386×386**，居中显示（四周各留 40px 黑边） |
| 背景 | **纯黑 #000000**，不要透明底、渐变、纹理或暗角 |
| 交付格式 | PNG，sRGB，不透明（无 alpha），8 位 |
| 设备内格式 | Mac 自动转为 JPEG（质量约 85），单张目标 ≤ 40KB |

画布外接圆就是屏幕可视范围：四个角会被裁掉，**主体必须在直径 386 的圆内**。

## 2. 安全区（画布坐标，左上角为 0,0）

屏幕上叠加的界面会盖住以下区域，**不要放五官或重要细节**：

| 区域 | 画布范围 | 叠加内容 |
|---|---|---|
| 顶部 | y < 20，x 125–261 | 时间（黑底圆角条） |
| 底部 | y > 366，x 103–283 | 状态栏：助手名、连接图标、电量 |
| 右侧 | x > 335，y 70–310 | 提醒标识（最多 5 个圆形徽章，半径 20） |

字幕气泡会在说话时出现在画面下半部，但它会短暂遮挡，不需要避让。

建议：**脸部（眼睛到嘴）放在画布中心 260×200 的范围内**，头发可以延伸到顶部，身体可以延伸到底部。

## 3. 必需帧：16 张（4 种嘴型 × 4 种眼睛）

文件名 `base_m{嘴}_e{眼}.png`，嘴 0–3，眼 0–3：

| 编号 | 嘴型 m | 眼睛 e |
|---|---|---|
| 0 | 闭嘴（自然微笑） | 完全睁开 |
| 1 | 微张（说话轻音） | 微垂（放松，约睁开 80%） |
| 2 | 半张（普通发音） | 半闭（约 40%） |
| 3 | 大张（重音、元音 a/o） | 完全闭上 |

设备如何使用：
- **说话**：随语音音量在 m0–m3 之间快速切换，所以四张嘴型必须是**同一张嘴的连续开合**，形状过渡自然。
- **眨眼与闭眼**：眨眼和闭眼过渡时依次使用 e0 → e3，所以眼睛也要是**同一双眼的连续闭合**。
- 嘴和眼会任意组合（例如说话时眨眼），16 张都要画齐。

**最重要的要求：除了嘴和眼睛，16 张图其余像素完全一致。** 头发、脸型、身体、光影、位置、配色一个像素都不能动，否则说话时整张图会抖动闪烁。推荐做法：先画一张底图（m0_e0），再只修改眼睛和嘴的区域生成其余 15 张。

参考：仓库自带的三套形象（`avatars/*/preview.png` 是 4×4 拼图），以及上游内置脸 `firmware/data_stopwatch/base_m*_e*.jpg`，可以对照帧的含义和幅度。

## 4. 可选帧

| 文件 | 含义 | 状态 |
|---|---|---|
| `happy.png` | 开心表情，用于提醒到达、任务完成，要求见 4.1 | 第一阶段支持 |
| `idle_00.png` … `idle_11.png` | 待机循环（呼吸、轻微晃头发），8–12 帧，首尾可无缝衔接 | 第二阶段，固件尚未支持 |
| `think_00.png` … `think_07.png` | 思考中（助手执行任务时），循环 | 第二阶段 |
| `listen.png` | 倾听（按住 A 录音时），可以是侧耳、专注表情 | 第二阶段 |

第二阶段的帧可以先画，同样遵守「只改动画部位、其余像素不变」的原则；等固件支持后直接可用。

### 4.1 开心表情 `happy.png`

用途：X 提醒到达、助手任务完成时短暂显示（约 1–2 秒），然后回到基础帧。它是整套里**情绪最明显的一张**，一眼就要看出“开心”，不能只是平静地闭眼。

**必须和 16 张基础帧都不同。** 特别是不能直接复用 `base_m0_e3`（闭嘴 + 闭眼）。基础帧的 e3 是“放松闭眼”，happy 是“笑到眯眼”，两者要明显区分。

| 部位 | 要求 |
|---|---|
| 眼睛 | 笑眼：向上弯的弧线（^^），比 e3 弯得更明显、更饱满；可以略微上提，表现“笑得眯起来” |
| 嘴 | 张开的笑，例如 D 形或上宽下窄的开口笑，可露出口腔或舌头的色块；比 m0 的微笑大一圈。不要用 m1–m3 的说话嘴型 |
| 脸颊 | 腮红比基础帧更明显（加深或扩大），角色本来没有腮红的，可以加一点暖色光晕或亮度提升 |
| 点缀（可选） | 头旁边 1–3 个小星星、音符或闪光等简单符号，形状要大而简洁；必须在画布圆内，且不进入第 2 节的遮挡区 |
| 身体与其余部分 | 头发、脸型、身体、配饰、位置、光影与 m0_e0 **像素一致**，切换时不跳动 |

改动范围：只改脸部（眼、嘴、脸颊）和可选点缀所在的位置，整体仍在中心 260×200 的建议区附近，其余像素差为 0。

按角色性格调整幅度：温和的角色可以是“眯眼 + 张嘴笑 + 腮红”，安静克制的角色可以是“笑眼弧 + 小开口笑 + 发光部件稍亮”，但都要比基础帧明显开心。

规格和基础帧相同：386×386、不透明、纯黑底，转为 JPEG（质量 85）后 ≤ 40KB。preview.png 不需要包含 happy，可另外附一张 `happy-preview.png`，左右并排放 `base_m0_e0` 和 `happy`，方便对比。

## 5. 风格与内容

- 原创角色，**不要使用现有动漫、游戏、品牌的角色或商标**。
- 黑底屏幕上要清楚：主体以中高亮度为主，边缘干净，避免大面积深色衣服和黑底融为一体。
- 线条不要太细，屏幕小、观看距离远，细节宜简洁；避免噪点、颗粒和细碎纹理（会让 JPEG 变大、变花）。
- 每套形象画风统一；不同套之间可以完全不同（例如一套人物、一套动物、一套极简表情）。

## 6. 交付结构

每套放一个文件夹：`avatars/<形象ID>/`，形象 ID 用 1–20 位小写英文、数字和连字符，例如 `snow-girl`、`cat-orange`。

```
avatars/snow-girl/
├── avatar.json          # 必需，描述信息
├── base_m0_e0.png … base_m3_e3.png   # 必需，16 张
├── happy.png            # 可选
├── idle_00.png …        # 可选（第二阶段）
└── preview.png          # 必需，4×4 拼图预览：行=嘴 m0–m3，列=眼 e0–e3
```

`avatar.json`：

```json
{
  "id": "snow-girl",
  "name": "雪团",
  "version": 1,
  "description": "银发少女，浅蓝和服",
  "frames": { "base": 16, "happy": true, "idle": 0, "think": 0, "listen": false }
}
```

## 7. 交付前自检

- [ ] 16 张 `base_m*_e*.png` 齐全，全部 386×386、不透明、纯黑背景
- [ ] 任意两张之间，嘴和眼以外的像素差为 0（可用图像差分检查）
- [ ] 嘴型 m0→m3 是逐步张开，眼睛 e0→e3 是逐步闭合
- [ ] 五官不在第 2 节的遮挡区域内
- [ ] 如有 `happy.png`：与 16 张基础帧都不相同（不能等于 m0_e3），脸部以外与 m0_e0 像素差为 0，点缀不进遮挡区
- [ ] `preview.png` 和 `avatar.json` 已生成
- [ ] 单张 PNG 转 JPEG（质量 85）后 ≤ 40KB，整套 ≤ 0.8MB

## 8. 容量参考

设备形象存储区约 5.5MB。只含必需帧时每套约 0.5MB，可放 8–10 套；带待机动画的套约 0.8–1MB。同一时间只加载当前一套，多套不增加运行内存。

## 9. 设备上如何存放

- 上传时 Mac（`src/avatars.py`）把 PNG 转成基线 JPEG（质量 85、4:2:0），按 4KB 分块写入设备 LittleFS 的 `/av/<id>/`，每个文件 CRC-32 校验通过后才替换旧文件，另写一份 `meta.json`。
- 当前形象记在 `/av/active`，重启后保持。设备优先读当前形象目录里的同名图，缺的（如上游的摸头、转头动画）回落到根目录的内置图。
- 开心表情：任务播报或 X 提醒播报结束、设备回到待机后显示 `happy.jpg` 2 秒；开始录音立即取消。

## 10. 给 AI 出图的建议

1. 先出一张高分辨率主视觉（角色全身、纯黑背景），定下造型和配色。
2. 只用这张主视觉生成 386×386 的 `m0_e0` 底图；之后**只在眼睛和嘴的区域**合成其余 15 帧和开心表情，不要让模型分别重画整张图，否则身体会抖。
3. 用图像差分自检第 7 节的每一条，再在控制台上传、到设备上看实际效果。
